# 狼人杀模式（路线 A）设计说明

> 定位：**最小垂直切片**。只做「模式身份 + 私有信息 + 独立提示词覆盖层 + 读档还原」四件事，
> 不新增动作类型、不新增 World 子系统、不改存档字段、不改公开契约。

## 1. 为什么走「配置化身份扮演」而不是完整规则模式

路线 A 用现有机制承载狼人杀的核心要素，避免触碰被冻结的世界语义：

| 狼人杀要素 | 本项目既有承载物 |
|---|---|
| 各自知道不同的秘密 | `game/agent/soul/AgentSoulProfile.gd` 的 `special_identities`（按居民私有） |
| 谁看到了什么 | `game/world/runtime/conflict/TownConflictKnowledgeProjector.gd` 的 `participant/witness/hearsay` |
| 白天集中表态 | `game/world/runtime/social/TownSocialMatterRuntime.gd` 的 `response_round` + `option_id` + `public_text` |
| 昼夜时段 | `game/agent/AgentContract.gd:11` 的六时段（含「夜里」） |
| 冲突与袭击 | `game/world/runtime/conflict/TownConflictRuntime.gd` + `profile-attack:<resident>:<target>` |

因此本切片**不发明新概念**，只把身份资料与模式规则喂给现有的决策管道。

## 3. 关键设计决策

### 3.1 覆盖层而不是替换提示词根

`AgentPromptCompiler._load_layer` 是**按目录 glob** 加载全部 `*.md` 的。如果直接把模式规则
丢进 `game/prompts/rules/`，**所有模式的每个居民**都会收到狼人杀规则。

因此采用「基线 + 覆盖层」：基线规则（决策契约、资料权威、事实边界）始终生效，
模式只在其后追加。这既避免了复制整份决策契约，也保证普通模式零影响。

### 3.2 模式不进入任何持久化通道

模式不写入 `openingConfig`、`session_config` 或存档区段——因为这些地方都有严格的
exact-keys 校验（`game/world/runtime/TownWorldOpeningConfig.gd:36`），加键会牵动冻结契约。

代价是读档时需要还原模式，解法是**从 Agent 私有身份索引反推**：
`AgentGameMode.detect_from_initialization()` 检查 `special_identities[].identity_id`
是否以 `AgentWerewolfRoleDealer.IDENTITY_PREFIX` 开头。`AgentSystem.restore_game()`
在构造居民运行时**之前**调用 `_adopt_detected_game_mode()`，因为提示词覆盖层在
居民运行时构造时就必须确定。

### 3.3 确定性随机

阵营分配复用项目既有 LCG 参数（modulus `2147483647`、multiplier `48271`，
与 `TownResidentConditionRuntime` 一致），先按居民 ID 排序再 Fisher-Yates 洗牌，
因此结果只依赖居民集合与 seed，与传入顺序、系统时间无关。

### 3.4 缺失覆盖层不静默降级

覆盖层读取本身宽松（缺目录不报错，否则普通模式会因 `get_load_errors()` 非空而无法初始化），
所以 `AgentGameMode.validate_overlay()` 在 `set_game_mode` 里显式检查 rs目录存在性，
避免狼人杀会话静默退化成普通模式。

## 4. 尚未接线的部分（刻意留白）

本切片把「模式规则能进提示词、身份能私有化、读档能还原」跑通，以下仍待接线：

1. **开局注入阵营**：`AgentGameMode.synthesize_soul_profiles()` 已能产出合格资料，
   但尚未接入 `TownNewGameOpeningCompiler.compile()`（该处属开局契约，改动需单独评估）。
2. **投票载体**：尚未创建以「怀疑/放逐」为主题的 social matter；目前依赖既有社会事项。
3. **胜负判定**：没有实现，也没有写入世界日志。
4. **模式入口**：没有新增 UI；目前只能由代码调用 `AgentSystem.set_game_mode("werewolf")`。

## 5. 验证方式（当前会话禁止运行）

本次改动**未运行任何命令**验证，仅做静态自查：

- `game/world/`、`game/ui/` 零改动 → 架构棘轮（`world_runtime_architecture_baseline.json`）不受影响。
- 未触碰持久化敏感前缀 → 不需要 `docs/persistence-changes/*.json` 登记。
- 两个新 `class_name` 在定义文件外均有匹配出现（`preload` 路径即构成匹配）→ 不产生新的零引用候选。
- 新增文件无 `.call(` / `callv(` / `Callable(` → 动态调用基线不受影响。
- 全部新增/修改文件为 LF，无 CR。
- `.gd` 与 `.gd.uid` 一一配对。

**仍需在允许运行时后补做的验证**：Godot 无窗口导入（确认脚本解析与 `.uid` 被接受、
导入后工作区保持干净）、`tools/guards/run_guards.sh`、以及一次狼人杀开局的行为走查。
